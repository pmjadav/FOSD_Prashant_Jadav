Practical 12: System V Shared Memory and IPC Performance

CO Mapping: CO2, CO5, CO6 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

A database server and an analytics application exchange large volumes of data with minimum latency. Design and implement interprocess communication using System V Shared Memory. Investigate Linux memory management using the /proc virtual file system. Evaluate communication latency, throughput, memory utilization, synchronization overhead, and compare shared memory with other IPC mechanisms to recommend the most suitable solution for high- performance applications.

2. Key Questions / Analysis / Interpretation

during/after Implementation

  1. Why is shared memory considered the fastest IPC mechanism?
  2. How do shmget(), shmat(), shmdt(), and shmctl() work together?
  3. Why is synchronization required when multiple processes access shared memory?
  4. Interpret memory information from /proc/meminfo and /proc/<pid>/maps.
  5. How does data size affect latency and throughput?
  6. Compare shared memory with pipes, FIFOs, and message queues.
  7. Recommend an IPC mechanism for database servers, multimedia systems, and AI inference pipelines.

3. Supplementary Problems

  • Easy: Exchange a string using System V Shared Memory.
  • Medium: Exchange a structure between two processes using shared memory.
  • Hard: Develop a multi-process shared-memory producer–consumer application with semaphore-based synchronization.

6. Learning Outcome

Students will implement shared-memory-based interprocess communication, analyze Linux memory management, evaluate IPC performance using quantitative metrics, compare alternative IPC mechanisms, and justify appropriate design decisions for high-performance systems.

7. Dataset / Test Data

Transfer data blocks of 1 KB, 4 KB, 64 KB, 1 MB, and 10 MB between processes. Measure execution time, latency, throughput, CPU utilization, and synchronization overhead. Observe memory statistics using /proc/meminfo, /proc/<pid>/status, /proc/<pid>/maps, and pmap.

11. Post Laboratory Work Description

Prepare a comparative report on System V Shared Memory, POSIX Shared Memory, mmap(), Message Queues, and UNIX Domain Sockets. Compare memory usage, kernel involvement, latency, throughput, scalability, synchronization requirements, and suitable application domains.
