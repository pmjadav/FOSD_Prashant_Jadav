Practical 3: POSIX File Operations and I/O Performance

CO Mapping: CO1, CO6 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

A company is developing a secure backup utility for Linux servers to copy large files, preserve metadata, detect I/O errors, and support random file access. Develop a Linux application using POSIX system calls such as open(), read(), write(), lseek(), stat(), and close() to perform file operations. Compare the implementation with buffered C library functions and recommend the most appropriate approach for different storage applications.

2. Key Questions / Analysis / Interpretation

Implementation CO1, CO6 8 | P a g e Differentiate POSIX system calls and standard C library file I/O. Why are file descriptors used after opening a file? How does buffer size influence execution time and throughput? Interpret the output of stat(), lsof, strace, and /proc/self/fd. How are file access permissions verified? Compare sequential and random file access using lseek(). Recommend an appropriate file I/O technique for large file transfers.

3. Supplementary Problems

Easy: Display file metadata using stat(). Medium: Implement random file access using lseek(). Hard: Develop a file synchronization utility that copies only modified files while preserving permissions.

4. Key Skills to be Addressed

Linux system programming POSIX file system calls Error handling using errno and perror() File descriptor management Performance evaluation Linux diagnostic tools

5. Applications

Backup and recovery software File synchronization tools Log management systems Database storage engines Operating system utilities Cloud storage applications

6. Learning Outcome

Students will implement Linux file operations using POSIX system calls, analyze file management mechanisms, compare different I/O techniques, interpret performance results, and justify appropriate file handling strategies for real-world applications.

7. Dataset / Test Data

Use text files of approximately 1 KB, 100 KB, 1 MB, 10 MB, and 100 MB. Perform sequential copying, random access using lseek(), metadata retrieval using stat(), and compare different buffer sizes (1 KB, 4 KB, 16 KB, and 64 KB). Record execution time, throughput, and system call counts.

8. Tools / Technology to be Used

Ubuntu 24.04 LTS GCC Compiler Linux Terminal POSIX APIs open(), read(), write(), lseek(), stat(), close() strace stat lsof /proc file system time utility 9 | P a g e

9. Total Hours of Problem Definition and Implementation

Activity Hours Problem Definition & Analysis 0.5 Implementation & Testing 1.5 Total 2.0

10. Total Hours of Engagement

Activity Hours Pre-laboratory Study 1 Laboratory Session 2 Result Analysis 1 Post-laboratory Work 1 Total 5

11. Post Laboratory Work Description

Prepare a comparative report on POSIX system calls, standard C library I/O, memory-mapped I/O (mmap), and sendfile(). Compare their performance, portability, kernel involvement, memory usage, and suitable application domains. Recommend an appropriate approach for large-scale backup and storage systems.
