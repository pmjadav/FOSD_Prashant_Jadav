Practical 1: Exploring OS Kernel Interfaces via System Calls

CO Mapping: CO1 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

A cloud service provider plans to develop a lightweight Linux monitoring utility that collects process, kernel and memory information with minimum overhead. Develop a Linux C application using system calls to retrieve process and system information, validate the results using the /proc virtual file system, compare both approaches and recommend the most suitable mechanism for building scalable monitoring software.

2. Key Questions / Analysis / Interpretation

Implementation

  1. How does a system call differ from accessing information through /proc?
  2. Compare information returned by getpid(), getppid(), uname() and sysinfo() with /proc.
  3. Which interface is faster and why?
  4. Which interface is more portable and maintainable?
  5. How should system call failures be handled?
  6. Recommend the best approach for a production monitoring application with justification.

3. Supplementary Problems

  • Easy: Display PID, PPID, UID and GID.
  • Medium: Display CPU and memory information using both sysinfo() and /proc.
  • Hard: Develop a mini system-monitoring utility that periodically reports CPU, memory and process statistics.

4. Key Skills to be Addressed

  • Linux programming using POSIX APIs
  • System call programming
  • Kernel-user space interaction
  • Error handling
  • Performance comparison
  • Technical report writing

5. Applications

  • Cloud monitoring agents
  • System administration
  • Performance monitoring
  • Container orchestration
  • Embedded Linux diagnostics
  • Server health monitoring

6. Learning Outcome

Students will implement Linux system calls, investigate kernel interfaces, compare system-call and /proc based approaches, interpret experimental results, and justify interface selection for system-monitoring applications.

7. Dataset / Test Data

Execute the program on Ubuntu 24.04 LTS. Record PID, PPID, kernel version, hostname, uptime, total RAM, free RAM and swap memory. Validate results using /proc/self/status, /proc/version, /proc/meminfo and /proc/uptime.

8. Tools / Technology to be Used

  • POSIX APIs
  • getpid(), getppid(), uname(), sysinfo()
  • ps

11. Post Laboratory Work Description

Compare Linux system calls with Windows API functions used to obtain process and system information. Prepare a two-page report comparing functionality, performance, portability and security. Suggest enhancements for developing a production-quality monitoring utility.
