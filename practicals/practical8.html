Practical 8: Reader–Writer Synchronization and Fairness

CO Mapping: CO3 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

CO3 17 | P a g e An online banking system allows thousands of customers to read account information while only authorized services update balances. Design and implement the Reader–Writer problem using POSIX mutexes and semaphores. Evaluate reader-preference, writer-preference, and fair synchronization policies by measuring throughput, waiting time, starvation, and CPU utilization. Recommend the most suitable synchronization policy for different application domains.

2. Key Questions / Analysis / Interpretation

Implementation

  1. Why is synchronization necessary in the Reader?Writer problem?
  2. Differentiate reader-preference, writer-preference, and fair synchronization policies.
  3. Why does reader-preference lead to writer starvation?
  4. How does the reader-to-writer ratio affect throughput and waiting time?
  5. Interpret starvation, CPU utilization, and context-switch statistics.
  6. Compare the performance of semaphore-based solutions and pthread_rwlock.
  7. Recommend the most appropriate synchronization policy for banking, digital libraries, and database systems with justification.

3. Supplementary Problems

  • Easy: Implement a reader-preference solution.
  • Medium: Compare reader-preference and writer-preference policies.
  • Hard: Implement a fair Reader–Writer solution using pthread_rwlock and compare its performance with semaphore-based implementation.

4. Key Skills to be Addressed

  • Concurrent programming
  • Reader?Writer synchronization
  • POSIX mutexes and semaphores
  • Reader?Writer locks (pthread_rwlock)
  • Performance analysis
  • Linux performance monitoring

5. Applications

  • Database systems
  • Banking applications
  • Reader-heavy web services
  • Digital libraries
  • File systems
  • Concurrent data structures

6. Learning Outcome

Students will implement the Reader–Writer problem using POSIX synchronization primitives, analyze different synchronization policies, evaluate starvation and fairness, and justify appropriate synchronization strategies for shared-data applications.

7. Dataset / Test Data

Execute experiments using 1, 2, 4, 8, and 16 reader threads with 1, 2, and 4 writer threads. Use read/write ratios of 90:10, 70:30, and 50:50. Record throughput, average waiting time, CPU utilization, starvation occurrences, execution time, and context switches.

11. Post Laboratory Work Description

Prepare a comparative report on semaphore-based Reader–Writer solutions, pthread_rwlock, sequence locks (seqlock), Read-Copy-Update (RCU), and optimistic concurrency control. Compare scalability, fairness, latency, starvation, and suitable application domains.
