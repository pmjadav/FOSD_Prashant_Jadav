Practical 8: Reader–Writer Synchronization and Fairness

CO Mapping: CO3 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

CO3 17 | P a g e An online banking system allows thousands of customers to read account information while only authorized services update balances. Design and implement the Reader–Writer problem using POSIX mutexes and semaphores. Evaluate reader-preference, writer-preference, and fair synchronization policies by measuring throughput, waiting time, starvation, and CPU utilization. Recommend the most suitable synchronization policy for different application domains.

2. Key Questions / Analysis / Interpretation

Implementation Why is synchronization necessary in the Reader–Writer problem? Differentiate reader-preference, writer-preference, and fair synchronization policies. Why does reader-preference lead to writer starvation? How does the reader-to-writer ratio affect throughput and waiting time? Interpret starvation, CPU utilization, and context-switch statistics. Compare the performance of semaphore-based solutions and pthread_rwlock. Recommend the most appropriate synchronization policy for banking, digital libraries, and database systems with justification.

3. Supplementary Problems

Easy: Implement a reader-preference solution. Medium: Compare reader-preference and writer-preference policies. Hard: Implement a fair Reader–Writer solution using pthread_rwlock and compare its performance with semaphore-based implementation.

4. Key Skills to be Addressed

Concurrent programming Reader–Writer synchronization POSIX mutexes and semaphores Reader–Writer locks (pthread_rwlock) Performance analysis Linux performance monitoring

5. Applications

Database management systems Online banking systems Digital libraries Search engines File system caches Cloud storage platforms

6. Learning Outcome

Students will implement the Reader–Writer problem using POSIX synchronization primitives, analyze different synchronization policies, evaluate starvation and fairness, and justify appropriate synchronization strategies for shared-data applications.

7. Dataset / Test Data

Execute experiments using 1, 2, 4, 8, and 16 reader threads with 1, 2, and 4 writer threads. Use read/write ratios of 90:10, 70:30, and 50:50. Record throughput, average waiting time, CPU utilization, starvation occurrences, 18 | P a g e execution time, and context switches.

8. Tools / Technology to be Used

Ubuntu 24.04 LTS GCC Compiler Linux Terminal POSIX Threads pthread_mutex_t POSIX Semaphores (sem_t) pthread_rwlock top -H ps -eLf perf stat vmstat strace

9. Total Hours of Problem Definition and Implementation

Activity Hours Problem Definition & Analysis 0.5 Implementation & Testing 1.5 Total 2.0

10. Total Hours of Engagement

Activity Hours Pre-laboratory Study 1 Laboratory Session 2 Result Analysis 1 Post-laboratory Work 1 Total 5

11. Post Laboratory Work Description

Prepare a comparative report on semaphore-based Reader–Writer solutions, pthread_rwlock, sequence locks (seqlock), Read-Copy-Update (RCU), and optimistic concurrency control. Compare scalability, fairness, latency, starvation, and suitable application domains.
