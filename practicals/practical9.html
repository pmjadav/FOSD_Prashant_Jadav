Practical 9: Anonymous Pipes for Interprocess Communication

CO Mapping: CO3 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

A Linux-based log processing system transfers data between related processes using shell-like pipelines. Design and implement anonymous pipe-based interprocess communication (IPC) using the pipe() system call. Evaluate communication latency, throughput, blocking behavior, message size, and process synchronization. Compare anonymous pipes with other IPC mechanisms and recommend the most appropriate IPC method for CO3 19 | P a g e different application scenarios.

2. Key Questions / Analysis / Interpretation

Implementation Why can anonymous pipes communicate only between related processes? How does the pipe() system call establish communication? What is the difference between blocking and non-blocking pipe operations? How does message size affect latency and throughput? Interpret observations obtained using strace, lsof and /proc. Compare anonymous pipes with FIFOs, shared memory and message queues. Recommend an IPC mechanism for shell pipelines, logging systems and streaming applications.

3. Supplementary Problems

Easy: Implement parent-to-child communication using a single anonymous pipe. Medium: Develop bidirectional communication using two anonymous pipes. Hard: Implement a multi-stage shell pipeline using multiple child processes and anonymous pipes.

4. Key Skills to be Addressed

Linux process programming Interprocess communication Anonymous pipe programming Process synchronization Performance analysis Linux diagnostic utilities

5. Applications

Unix shell pipelines Log processing systems Compiler toolchains Command chaining utilities Batch processing systems Operating system utilities

6. Learning Outcome

Students will implement anonymous pipe-based IPC, analyze communication performance, evaluate blocking and synchronization behavior, compare different IPC mechanisms, and justify IPC selection for Linux applications.

7. Dataset / Test Data

Transfer text messages and files using message sizes of 64 B, 1 KB, 4 KB and 64 KB. Execute experiments with 100, 1,000 and 10,000 messages in blocking and non-blocking modes. Measure latency, throughput, execution time, CPU utilization and context switches.

8. Tools / Technology to be Used

Ubuntu 24.04 LTS GCC Compiler Linux Terminal POSIX APIs 20 | P a g e pipe(), read(), write(), close(), fork() strace lsof ps /proc file system time utility

9. Total Hours of Problem Definition and Implementation

Activity Hours Problem Definition & Analysis 0.5 Implementation & Testing 1.5 Total 2.0

10. Total Hours of Engagement

Activity Hours Pre-laboratory Study 1 Laboratory Session 2 Result Analysis 1 Post-laboratory Work 1 Total 5

11. Post Laboratory Work Description

Prepare a comparative report on Anonymous Pipes, Named Pipes (FIFO), System V Message Queues, Shared Memory and UNIX Domain Sockets. Compare communication speed, kernel involvement, programming complexity, scalability and suitable application domains.
