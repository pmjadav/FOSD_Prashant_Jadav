Practical 6: Race Conditions and Synchronization with Mutexes and Semaphores

CO Mapping: CO3 · Laboratory session: 2 hours

Assessment: Each practical is assessed out of 10 marks. Students perform the experiment, record observations, complete supplementary work and answer viva questions.

1. Problem Definition

A banking system processes thousands of concurrent transactions that update shared account balances. Develop a multithreaded application that demonstrates race conditions and then eliminates them using POSIX mutexes and semaphores. Compare synchronized and unsynchronized executions, evaluate correctness, performance, synchronization overhead, and recommend an appropriate synchronization mechanism.

2. Key Questions / Analysis / Interpretation

Implementation Explain the cause of race conditions in concurrent programs. Differentiate mutexes and semaphores with suitable use cases. Why does the unsynchronized program produce inconsistent results? How do thread count and contention affect execution time? Interpret context-switch statistics and synchronization overhead. Compare correctness and performance of mutex and semaphore implementations. Recommend a synchronization strategy for banking or reservation systems with justification.

3. Supplementary Problems

Easy: Protect a shared counter using pthread_mutex_t. Medium: Compare mutex and semaphore implementations for the same application. Hard: Develop a thread-safe logging service using mutexes, semaphores, or CO3 14 | P a g e atomic operations and compare performance.

4. Key Skills to be Addressed

Concurrent programming Critical section identification POSIX mutex programming POSIX semaphore programming Performance analysis Debugging multithreaded applications

5. Applications

Online banking systems Airline reservation systems Database transaction processing Operating system kernels Web servers Industrial automation

6. Learning Outcome

Students will implement synchronization using POSIX mutexes and semaphores, analyze race conditions, evaluate synchronization overhead, compare alternative synchronization techniques, and justify suitable mechanisms for concurrent software systems.

7. Dataset / Test Data

Execute the application with shared counters initialized to zero using 2, 4, 8 and 16 threads. Each thread performs 10,000, 100,000 and 1,000,000 increment operations. Record final counter values, execution time, CPU utilization and context switches for synchronized and unsynchronized executions.

8. Tools / Technology to be Used

Ubuntu 24.04 LTS GCC Compiler Linux Terminal POSIX Threads pthread_mutex_t POSIX Semaphores (sem_t) perf stat top -H ps -eLf strace time

11. Post Laboratory Work Description

Prepare a comparative study of mutexes, semaphores, spinlocks, reader- writer locks, monitors and atomic operations. Discuss their implementation complexity, scalability, latency and suitable application domains.
